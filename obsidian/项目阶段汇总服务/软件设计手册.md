# 项目阶段汇总服务 - 软件设计手册

## 一、系统概述

项目阶段汇总服务用于统一汇总分布在多台业务服务器上的考试项目阶段数据，提供统一看板查询、数据导出、负责人分配及钉钉通知等功能。

系统适用于以下场景：
- 多台 SQL Server / MySQL 业务数据库分散部署
- 业务服务器处于不同网络环境（VPN、内网隔离）
- 需要统一视角掌握所有项目的阶段进度

## 二、总体架构

系统由五个核心组件构成：

```
┌──────────┐     HTTPS      ┌──────────┐    AES-GCM 加密    ┌──────────┐
│  浏览器   │ ◄──────────► │  主服务   │ ◄────────────────► │  Agent   │
│ （前端）  │               │ （IIS）   │                    │（业务机）│
└──────────┘               └────┬─────┘                    └────┬─────┘
                                │                               │
                           SQL 连接                         本地 SQL 连接
                                │                               │
                         ┌──────▼──────┐                 ┌──────▼──────┐
                         │   中心库     │                 │   源数据库   │
                         │ SQL Server  │                 │ SQL/MySQL   │
                         └─────────────┘                 └─────────────┘
```

| 组件 | 技术栈 | 职责 |
|------|--------|------|
| 前端 | 单页 HTML + JavaScript | 登录、查询筛选、看板展示、配置管理 |
| 主服务 | ASP.NET Core 8 Minimal API | 认证权限、配置管理、调度、Agent 调用、中心表读写、导出、钉钉通知 |
| Agent | Python（Debian）/ .NET（Windows） | 接收加密任务、本地查询源数据库、返回标准化结果 |
| 中心库 | SQL Server | 存储汇总后的阶段数据、项目元数据 |
| 本地缓存 | SQLite | 保存最近一次数据快照，便于故障排查 |

## 三、数据查询方式

### 3.1 数据刷新流程

主服务**不直接访问**业务数据库。所有数据采集通过部署在业务服务器上的 Agent 完成：

1. 主服务读取已配置的服务器列表
2. 主服务构造查询定义（需要查哪些表、执行什么 SQL）
3. 主服务使用 AES-GCM 加密请求体，通过 HTTP 发送至 Agent
4. Agent 解密请求，在**本机**连接源数据库执行查询
5. Agent 返回标准化的阶段记录和人数统计
6. 主服务汇总结果，写入中心表

### 3.2 页面查询流程

前端查询**只读取中心库**，不触及任何业务数据库：

1. 用户在页面设置筛选条件（时间段、项目名、阶段名等）
2. 主服务从中心表查询匹配的数据
3. 服务端根据用户角色进行权限过滤
4. 返回看板数据和统计摘要

### 3.3 定时调度

系统支持配置定时刷新和通知：
- **阶段数据刷新**：按配置的时间点自动调用 Agent 采集最新数据
- **人数统计刷新**：独立时间点刷新报名/准考证人数
- **钉钉通知**：在配置的时间点推送当日即将开始的项目阶段

## 四、安全设计

### 4.1 传输安全

#### 浏览器 ↔ 主服务

- 使用 **HTTPS（TLS）** 加密，通过域名 + SSL 证书保护
- 所有 API 请求均通过 HTTPS 传输

#### 主服务 ↔ Agent

- 请求体使用 **AES-256-GCM** 对称加密
- 加密密钥由共享密钥经 SHA-256 派生
- 每次请求生成随机 Nonce，防止重放
- **加密保护的内容包括**：源库账号密码、中心库账号密码、查询定义

```
加密信封格式：
{
  "version": 1,
  "nonce": "<Base64 随机值>",
  "ciphertext": "<Base64 加密数据>",
  "tag": "<Base64 认证标签>"
}
```

> Agent 端口仅在内网开放，不暴露到公网。数据库凭据**从不以明文通过网络传输**。

### 4.2 认证与权限

#### 认证方式

- Cookie Authentication（ASP.NET Core）
- 首次登录需创建管理员账号
- 首次分配的账号强制修改密码

#### 密码存储

- 使用 **PBKDF2 + SHA-256** 进行密码哈希
- 每个用户独立盐值（Salt）
- 不存储明文密码

#### 角色权限模型

| 能力 | admin | internal | external |
|------|:-----:|:--------:|:--------:|
| 查看全部项目 | ✅ | ✅ | ❌ |
| 仅查看自己负责的项目 | - | - | ✅ |
| 管理服务器配置 | ✅ | ✅ | ❌ |
| 管理中心库/调度/用户 | ✅ | ❌ | ❌ |
| 修改项目负责人 | ✅ | ✅ | ❌ |
| 修改应用服务器分配 | ✅ | ✅ | ✅（仅自己项目） |
| 手工刷新数据 | ✅ | ✅ | 需管理员授权 |

#### 数据级权限

external 用户的数据过滤**在服务端完成**，不依赖前端裁剪：
- 根据项目元数据中的负责人（maintainer）字段
- 按 server_name + exam_code 组合匹配
- 未分配负责人的项目对 external 用户不可见

### 4.3 配置文件安全

- 服务器配置（含数据库账号密码）保存在服务端本地加密文件中
- 配置文件不纳入代码仓库
- Agent 密钥通过环境变量或独立配置文件提供，不硬编码

### 4.4 钉钉通知安全

- 钉钉机器人 Webhook 使用 **HMAC-SHA256 签名**验证
- 钉钉转发代理通过 token 进行身份验证
- 代理心跳注册使用与主服务一致的签名密钥

```
                 ┌────▼────┐
                 │  防火墙  │
                 └────┬────┘
                      │ 443 (HTTPS)
              ┌───────▼───────┐
              │   主服务 (IIS) │ ← 172.31.78.175
              └───┬───────┬───┘
                  │       │
        ┌─────────▼─┐  ┌──▼──────────┐
        │ Agent(Win) │  │ Agent(Linux)│
        │ :5100      │  │ :5200       │
        └─────┬──────┘  └──┬──────────┘
              │             │
        ┌─────▼──────┐  ┌──▼──────────┐
        │ SQL Server │  │   MySQL     │
        └────────────┘  └─────────────┘
```

- Agent 端口仅对主服务内网开放
- 源数据库仅允许本机 Agent 访问
- 主服务通过 HTTPS 对外提供服务

## 六、使用说明

### 6.1 登录与初始化

1. 首次访问时系统要求创建管理员账号
2. 管理员登录后可创建其他用户并分配角色
3. 新用户首次登录需修改密码

### 6.2 数据查询

1. 点击「开始查询」，系统从中心库读取最新数据
2. 支持按以下条件筛选：
   - 时间段（只看开始 / 只看结束 / 都看）
   - 项目名关键字
   - 阶段名关键字（支持 `/` 分隔多个）
   - 数据库关键字
   - 考试代码
3. 查询结果以看板形式展示，分为「正在进行」「即将开始」「已结束」三列
4. 每列顶部显示汇总统计（项目数、报名人数、准考证人数等）
5. 支持导出 Excel

### 6.3 用户管理（管理员）

1. 点击顶部「用户管理」按钮
2. 输入用户名，选择角色后点击「创建」：
   - **admin**：超级管理员，拥有全部权限
   - **internal**：内部用户，可查看全部项目、管理服务器和项目配置
   - **external**：外部用户，仅能查看分配给自己的项目
3. 新用户默认密码由管理员告知，首次登录强制修改

### 6.4 给外部用户分配项目

外部用户（external）默认看不到任何项目，需要管理员或内部用户为其分配负责人：

1. 在看板中找到需要分配的项目卡片
2. 点击卡片上的 **⚙ 配置按钮**
3. 在弹出的项目配置窗口中，「负责人」下拉框选择对应的外部用户
4. 点击「保存」

分配后，该外部用户登录即可看到自己负责的项目。

> 一个项目只能分配一个负责人。如需多人查看同一项目，可将这些用户设为 internal 角色。

### 6.5 分配应用服务器

为项目指定所部署的应用服务器，便于运维人员了解资源分布：

1. 点击项目卡片上的 **⚙ 配置按钮**
2. 在弹出窗口中，勾选该项目对应的应用服务器（支持多选）
3. 点击「保存」

应用服务器候选列表由管理员或内部用户在「应用服务器配置」中维护（每行一个服务器名称）。

> 外部用户也可以修改自己所负责项目的应用服务器分配。

### 6.6 钉钉通知

系统支持定时推送当日即将开始的项目阶段到钉钉群：

1. 管理员在「定时任务」配置中填写钉钉机器人 Webhook 和签名密钥
2. 设置推送时间（如每天 08:00）
3. 系统在指定时间自动推送群消息，包含当日所有即将开始的阶段
4. 各用户也可配置个人钉钉机器人，接收自己负责项目的单独推送

### 6.7 服务器配置（管理员/内部用户）

1. 点击顶部「服务器配置」按钮
2. 添加业务服务器，填写：
   - 服务器名称（显示名）
   - 数据库类型（SQL Server / MySQL）
   - 数据库地址、端口、账号、密码
   - Agent 端口和密钥
3. 点击「测试连接」验证 Agent 可达性
4. 启用后即可参与数据刷新

## 七、技术要点总结

| 要点 | 说明 |
|------|------|
| 数据库凭据传输 | AES-256-GCM 加密，不传明文 |
| 密码存储 | PBKDF2 + SHA-256 哈希，独立盐值 |
| 数据权限 | 服务端按角色过滤，非前端裁剪 |
| 源库访问方式 | Agent 本地访问，主服务不直连源库 |
| 页面查询来源 | 仅读取中心库，不触及业务库 |
| 通信协议 | 外部 HTTPS，内部 HTTP + AES-GCM |
| 配置存储 | 本地加密文件，不入代码仓库 |
